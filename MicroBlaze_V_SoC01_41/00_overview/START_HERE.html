16 KB는 초기 최소 SoC 기준이다. 후속 실습에서 코드·데이터·스택·힙이 BRAM을 초과하면 링커 맵으로 필요한 용량을 확인한 뒤 하드웨어와 XSA·플랫폼을 함께 갱신한다. 장별 주소 예시를 실제 생성값으로 가정하지 않는다.

실습 순서

  1. 01–05장: CPU·BRAM·클록·리셋을 만들고 ELF 실행과 메모리 맵을 확인한다.
  2. 06–10장: GPIO·UART·Timer·Interrupt를 순서대로 연결한다.
  3. 11–23장: 레지스터 맵과 Custom AXI IP를 구성하고 기능·CDC·타이밍·자원을 검증한다.
  4. 24–30장: MAC·PE·제어·메모리 공급·데이터 흐름·양자화를 단계별로 검증한다.
  5. 31–36장: CPU–NPU 연결과 인터럽트·버퍼·작업 제어·소프트웨어를 통합한다.
  6. 37–41장: 성능 개선 후 기능·타이밍·자원·전력·실측 근거로 최종 판정한다.

프로그램 실행 확인

  1. Vivado에서 설계와 주소를 확인하고 해당 bitstream을 포함한 XSA를 내보낸다.
  2. MicroBlaze V용 Platform과 standalone Domain을 생성한다. 하드웨어가 바뀌면 플랫폼을 갱신한다.
  3. 해당 장의 C 소스를 빌드하고 ELF의 메모리 배치를 확인한다. 이전 MicroBlaze용 BSP·ELF를 재사용하지 않는다.
  4. 동일 하드웨어의 bitstream과 ELF를 다운로드하고 실행한다.
  5. 03장은 Watch 값, 07장은 Local Echo를 끈 UART 응답처럼 각 장의 기대 결과로 판정한다.

RTL 시뮬레이션 통과, C 문법 검사 통과, 타깃 빌드 성공, 보드 실행 성공은 각각 별개의 결과다.

파일 사용

  • 압축을 전체 해제한 뒤 맨 위 index.html을 연다. 인터넷 없이 본문·내장 그림·코드를 볼 수 있다. 공식 문서 링크는 인터넷 연결이 필요하다.
  • 좌측에서 장과 절을 찾고, 실습 파일에서 해당 장의 소스를 연다. 이 장 검증에는 수행한 검사와 미검증 범위가 있다.
  • 코드 복사는 보이는 들여쓰기와 줄바꿈을 보존한다. 브라우저가 복사를 제한하면 선택된 코드를 Ctrl+C / Command+C로 복사한다.
  • 키보드 Tab으로 이동하고, 표·코드의 스크롤 영역에서는 방향키를 사용한다. 인쇄는 Ctrl+P / Command+P를 사용한다.

SECTION 01

01장 Block Design에서 계속 진행

  1. 기존 Block Design 열기

    Vivado의 Sources → Design Sources에서 01장에 저장한 soc01_mb_bram.bd를 연다. MicroBlaze V, 16 KB Local BRAM, Clocking Wizard, Processor System Reset은 다시 생성하지 않는다.

  2. Clocking Wizard 설정 열기

    Diagram에서 clk_wiz_1을 더블클릭 → Clocking Options를 확인한다.

  3. Basys3 클럭 입력 확인

    Basys3 W5는 단일 100 MHz 클럭 입력이므로 Primary Input Source는 Single ended clock capable pin, Primary Input Frequency는 100.000 MHz로 맞춘다. clk_out1도 설정값 100 MHz인지 확인한다.

  4. 입력 포트 형태 확인

    CLK_IN1_D가 있다면 차동 입력 설정인지 확인하고 단일 입력으로 변경한다. Ctrl+S로 저장한다.

SECTION 02

Clock / Reset 외부 포트 연결

01장에서 생성된 Clock/Reset IP를 Basys3의 외부 Clock 및 버튼 신호에 연결한다. 현재 Diagram의 외부 포트명과 01장의 XDC를 대조한다.

  1. Clock 외부 포트

    단일 입력으로 설정된 clk_wiz_1의 Clock 입력을 우클릭 → Make External로 외부 포트를 만든다. 생성된 외부 포트명을 확인한다.

  2. Reset 외부 포트

    clk_wiz_1/reset의 기존 배선을 확인한 후 필요하면 Make External을 실행한다. 동일한 외부 Reset 신호를 rst_clk_wiz_1_100M/ext_reset_in에 연결한다.

  3. 중복 포트 확인

    이미 외부 포트가 생성되어 있다면 새로 만들지 않는다. 실제 외부 Clock과 Reset 포트명을 SECTION 04에서 기존 XDC와 대조한다.

SECTION 03

Processor System Reset 설정 · 연결

Basys3 Center Button은 누르면 High가 되는 입력으로 사용하므로 ext_reset_in도 Active-High로 맞추는 것이 직관적이다.

항목SoC 02 기준이유
External Reset Logic LevelActive-HighBTNC 누름 = High
Auxiliary Reset미사용현재 내부 보조 Reset 없음
MicroBlaze Debug ResetMDM V 연결Debug Reset 경로 유지
dcm_lockedclk_wiz_1/lockedClock 안정 상태 반영
slowest_sync_clk100 MHz System Clock현재 단일 Clock Domain

외부 Push Button은 FPGA Clock과 비동기이며 기계적 바운스가 발생할 수 있다. Processor System Reset은 Reset 입력 검출과 동기화 기능을 제공하지만, 이를 일반적인 Push Button Debouncer로 간주하지 않는다.

MDM V의 Debug_SYS_Rst는 mb_debug_sys_rst로 연결한다. aux_reset_in을 사용하지 않으면 Active-High 설정에서 0으로 고정한다.

SECTION 04

01장 XDC 설정 확인

01장에서 등록한 Basys-3-Master.xdc를 다시 설정하지 않고, 현재 Block Design의 외부 포트와 일치하는지만 확인한다.

  1. 기존 XDC 확인

    Sources → Constraints에서 Basys-3-Master.xdc를 열어 활성화된 Clock 및 Reset 제약을 확인한다.

  2. BD 포트 대조

    외부 포트 clk, btnC가 XDC의 get_ports와 일치하는지 확인한다. 해당 포트가 이미 일치하므로 변경하지 않는다.

SECTION 05

신호 경로 추적

다음 신호가 실제 Diagram에서 연결되었는지 확인한다. 외부 Clock/Reset 포트명은 현재 회로도에서 확인한 이름을 사용한다.

  1. Primary Clock

    BD 외부 Clock → clk_wiz_1 단일 입력

  2. Generated Clock

    clk_wiz_1/clk_out1 → microblaze_riscv_0/Clk

  3. Lock

    clk_wiz_1/locked → rst_clk_wiz_1_100M/dcm_locked

  4. External Reset

    BD 외부 Reset → rst_clk_wiz_1_100M/ext_reset_in

  5. CPU Reset

    rst_clk_wiz_1_100M/mb_reset → microblaze_riscv_0/Reset

이 다섯 경로가 설명과 실제 Block Design에서 일치해야 SoC 02의 핵심 구조가 완성된다.
SECTION 06

Validate Design — 첫 번째 Stage Gate

  1. 첫 Validate Design

    외부 Clock/Reset 연결 및 기존 XDC와의 일치 확인 후 Ctrl+S로 Block Design을 저장하고 Validate Design을 실행한다.

  2. Clock Association

    MicroBlaze V, Local Memory, Processor System Reset이 동일한 100 MHz Clock에 연결되었는지 확인한다.

  3. Reset Association

    AXI 계층이 아직 최소 구성이라도 interconnect_aresetn, peripheral_aresetn이 올바른 극성으로 생성되는지 확인한다.

Gate 1 PASS 기준: Clock 입력 100 MHz, Clock Wizard lock 경로, Processor System Reset 입력/출력, MicroBlaze V Reset 경로가 모두 연결되고 Validate Design이 오류 없이 완료되어야 한다. Messages에서 Clock/Reset과 미연결 Interface 오류를 함께 확인한다. 사용하지 않을 AXI 인터페이스의 미완성 주소 경고도 원인을 확인한다.
정상 결과: Validation successful 메시지를 확인한다. Error 또는 Critical Warning이 없어야 한다. M_AXI_DP 주소 경로 미완성 경고(BD 41-2670)는 현재 미연결 AXI 확장 포트와 구분하여 후속 주변장치 연결 때 확인한다.
SECTION 07

Generate Output Products · HDL Wrapper

  1. Generate Output Products

    Sources에서 soc01_mb_bram.bd를 우클릭 → Generate Output Products를 실행한다. 기존 설정인 Out of context per IP를 사용한다.

  2. 생성 결과 확인

    Log에 합성용/시뮬레이션용 soc01_mb_bram.v, soc01_mb_bram_wrapper.v, soc01_mb_bram.hwh, soc01_mb_bram.hwdef 생성 메시지가 있는지 확인한다.

  3. HDL Wrapper · Top 확인

    Sources → Design Sources에서 soc01_mb_bram_wrapper가 프로젝트에 등록되어 Top으로 지정되었는지 확인한다. 생성 폴더에 soc01_mb_bram_wrapper.v 파일이 존재하는 것만으로는 Top 설정이 확인되지 않는다.

  4. 필요한 경우 Create HDL Wrapper

    Sources에 Wrapper가 없다면 soc01_mb_bram.bd 우클릭 → Create HDL Wrapper → Let Vivado tools manage wrapper and auto-update를 선택한다. 생성 후 Top 지정 여부를 다시 확인한다.

출력 파일 확인: Log에서 합성/시뮬레이션용 soc01_mb_bram.v, soc01_mb_bram_wrapper.v, soc01_mb_bram.hwh, soc01_mb_bram.hwdef 파일 생성 메시지를 확인한다. 파일 생성과 프로젝트 Top 지정은 별도 절차이다.
Design Sources → soc01_mb_bram_wrapper (Top) → soc01_mb_bram_i → MicroBlaze V · Local BRAM · Clock/Reset IP
HDL Wrapper는 Block Design을 감싸는 Shell/Wrapper로 유지한다. 계산, 상태 판단, Register Map 정책, FSM은 별도 RTL/IP에서 구현한다.
SECTION 08

Synthesis · Implementation · Generate Bitstream

  1. Run Synthesis

    Flow Navigator → Run Synthesis를 실행한다. 이미 성공했다면 다시 실행하지 않고 완료 상태를 확인한다.

  2. Run Implementation

    Flow Navigator → Run Implementation을 실행한다. Placement/Routing 완료 후 Design Runs에서 impl_1의 완료 상태를 확인한다.

  3. Timing 및 제약 확인

    Design Runs에서 WNS/TNS와 Failed Routes를 확인한다. XDC의 100 MHz Clock 제약과 clk(W5), btnC(U18) 포트를 점검한다. Critical Warning과 일반 Warning은 구분하여 확인한다.

  4. Generate Bitstream

    Flow Navigator → PROGRAM AND DEBUG → Generate Bitstream을 클릭한다. 완료되면 생성 메시지와 impl_1의 write_bitstream Complete 상태를 확인한다.

  5. Bitstream 파일 확인

    프로젝트의 *.runs/impl_1/에서 soc01_mb_bram_wrapper.bit 파일 생성 여부를 확인한다. 실제 파일명과 경로는 해당 Run 결과를 따른다.

Validate Design → HDL Wrapper → Synthesis → Implementation → Generate Bitstream
SECTION 09

Methodology Warning · XDC Clock 제약 확인

Vivado 2024.2의 Report Methodology에서 TIMING-6 Critical Warning 2건을 확인하였다. Basys-3-Master.xdc의 중복 가능성이 있는 create_clock -add 줄을 주석 처리하고 다시 구현한 결과, Critical Warning 0건 · Warning 4건으로 바뀌었다. write_bitstream Complete도 확인되었다.

항목변경 전변경 후
Critical Warning2건 (TIMING-6)0건
일반 Warning6건4건
Bitstream생성 완료write_bitstream Complete

1. XDC 변경 전후 비교

Clock 입력 물리 핀 W5와 I/O 규격 LVCMOS33는 변경하지 않는다. 실제로 변경한 부분은 Clock 생성 명령 한 줄이다.

## Clock signal
set_property -dict { PACKAGE_PIN W5   IOSTANDARD LVCMOS33 } [get_ports clk]
create_clock -add -name sys_clk_pin -period 10.00 -waveform {0 5} [get_ports clk]
## Clock signal
set_property -dict { PACKAGE_PIN W5   IOSTANDARD LVCMOS33 } [get_ports clk]
## Methodology 확인 후 해제 - 크리티컬 워닝 2건 발생
#create_clock -add -name sys_clk_pin -period 10.00 -waveform {0 5} [get_ports clk]

2. 변경 후 남은 Warning 4건

Warning건수의미와 확인 지점
LUTAR-12건Serial_Dbg_Intf 내부 LUT가 플립플롭의 비동기 Preset/Clear를 구동. 글리치가 의도치 않은 Reset을 발생시킬 위험이 있으므로 해당 경로와 Debug IP 구성을 점검한다.
TIMING-91건비동기 Clock Domain Crossing(CDC, 클럭 영역 교차) 경로에 인식 가능한 2단 동기화 구조가 확인되지 않음. report_cdc로 실제 경로를 확인한다.
TIMING-181건btnC 입력에 clk 기준 Input Delay가 없음. 비동기 버튼 Reset인지 확인하고 Reset 해제 경로와 타이밍 제약의 적절성을 검토한다.

3. Timing 제약 및 Warning 확인

Critical Warning이 사라졌더라도, Clock 제약이 실제로 적용되어 있는지를 확인해야 한다. Open Implemented Design → Tcl Console에서 실행한다.

# Primary Clock 및 Generated Clock의 주기·기원 확인
report_clocks

# 외부 clk 포트에 연결된 Clock 객체 확인
get_clocks -of_objects [get_ports clk]

# 누락된 Clock 및 미제약 경로 확인
check_timing -verbose

# Methodology Warning 재확인
report_methodology

# Clock Domain Crossing 상세 경로 분석
report_cdc
판정 기준: ① MicroBlaze V의 동작 Clock에 100 MHz(10 ns) 제약이 유효할 것, ② no_clock 등 예상하지 않은 미제약 경로가 없을 것, ③ TIMING-6이 재발하지 않을 것. 남은 LUTAR-1·TIMING-9·TIMING-18은 원인 확인 없이 무시하거나 임의의 set_false_path / set_input_delay로 경고만 숨기지 않는다.

공식 참고: AMD UG906 2024.2 · TIMING-9 · AMD UG906 2024.2 · Timing Signoff.

SUMMARY

SoC 02 완료 확인

  • 01장에서 생성한 MicroBlaze V 및 Local BRAM 구조를 그대로 이어서 사용했다.
  • clk_wiz_1의 입력을 Basys3 단일 100 MHz Clock으로 설정했다.
  • BD 외부 Clock/Reset 포트와 Processor System Reset 연결을 확인했다.
  • 기존 XDC의 get_ports가 실제 BD 외부 포트명과 일치한다.
  • W5 · U18 · 10 ns · LVCMOS33 제약을 확인했다.
  • Validate Design이 오류 및 Critical Warning 없이 완료되었다. 일반 Warning 3건은 별도로 확인했다.
  • 합성/시뮬레이션용 RTL과 .hwh, .hwdef 파일이 생성되었다.
  • soc01_mb_bram_wrapper를 프로젝트 Top으로 등록했다.
  • Synthesis · Implementation 완료 후 soc01_mb_bram_wrapper.bit 생성 결과를 확인한다.
  • create_clock -add 주석 처리 후 TIMING-6 중요 경고가 0건으로 감소했다. 남은 일반 Warning 4건과 실제 100 MHz Clock 제약은 별도로 점검한다.

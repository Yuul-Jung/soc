AXI GPIO - Switch 입력을 LED 출력으로

Vivado에서 AXI GPIO를 연결하고 Vitis에서 C 프로그램을 작성하여, Basys3 스위치 16개 상태를 LED 16개에 그대로 표시한다.

AXI GPIOAXI4-LiteDual ChannelVivado 2024.2Vitis 2024.2SW[15:0] → LED[15:0]

입력

Channel 2에서 Basys3 SW[15:0]을 읽는다.

CPU

MicroBlaze V가 AXI4-Lite Register를 Read/Write한다.

출력

Channel 1에서 LED[15:0]을 구동한다.

SoC 04 Memory Map→SoC 05 AXI→SoC 06 AXI GPIO→SoC 07 AXI UART Lite
SECTION 01

AXI GPIO 실습 목표

Basys3의 스위치 16개를 읽어서 같은 번호의 LED 16개를 켭니다. GPIO(지피아이오, 범용 입출력)는 스위치·LED 같은 간단한 주변장치를 제어하는 기능입니다.

SW[15:0] → AXI GPIO Channel 2 → MicroBlaze V → AXI GPIO Channel 1 → LED[15:0]
입력 조작예상 출력
SW0 ONLED0 ON
SW3 ONLED3 ON
SW0 + SW3 ONLED0 + LED3 ON

06장에서는 GPIO를 실제 보드에 연결하고 C 프로그램으로 제어합니다. AXI 신호의 상세 이론은 05장을 참고합니다.

SECTION 02

01장 프로젝트 복제 · Design Sources 정리

06장은 01장에서 검증된 MicroBlaze V + BRAM 프로젝트를 복제하여 이어서 만드는 장입니다. 04장은 같은 하드웨어를 이용한 메모리 실습이고, 05장은 AXI 이론이므로 06장 시작을 위해 SoC를 다시 만들지 않습니다. 01장 원본 HW와 기존 Vitis 프로젝트는 보존합니다.

01장 성공 프로젝트 → 06장으로 Save As → Block Design 이름 변경 → 새 HDL Wrapper/Top 지정 → 기존 Wrapper 정리 → AXI GPIO 추가

  1. 기존 01장 프로젝트 열기 — Vivado 2024.2에서 ~/soc/hw/soc01_microblaze_bram/soc01_microblaze_bram.xpr을 엽니다. microblaze_riscv_0, Local BRAM 16 KiB, MDM, Clocking Wizard, Reset 및 ILMB/DLMB를 확인합니다. 이때 M_AXI_DP는 주변장치 미연결 상태입니다.
  2. 06장 프로젝트로 복제 — File → Project → Save As를 실행해 soc06_axi_gpio 이름으로 ~/soc/hw/soc06_axi_gpio/에 저장합니다. 원래 01장 프로젝트를 덮어쓰지 않습니다.
  3. Block Design을 06장 이름으로 저장 — 복제본에 남아 있는 soc01_mb_bram을 열고 File → Save Block Design As에서 이름을 soc06_axi_gpio로 지정합니다. 실제 사용했던 설정은 Local to Project, Add to Design Sources, Include Comments 선택, Freeze boundary 해제입니다.
  4. 새 HDL Wrapper 생성 — Sources → Design Sources의 soc06_axi_gpio.bd를 우클릭하여 Create HDL Wrapper → Let Vivado manage wrapper and auto-update를 선택합니다. 생성된 soc06_axi_gpio_wrapper를 Set as Top으로 지정합니다.
  5. 기존 Wrapper 정리 — 더 이상 Top으로 사용하지 않는 soc01_mb_bram_wrapper는 Remove File from Project만 수행합니다. Delete files from disk는 선택하지 않습니다. 원본 Block Design이나 기존 01장 프로젝트 파일도 삭제하지 않습니다.
  6. Design Sources 및 IP 상태 확인 — 최종 Top이 soc06_axi_gpio_wrapper인지 확인합니다. Tools → Report → Report IP Status에서 기존 IP 9개가 모두 Up-to-date / No changes required였던 정상 화면을 기준으로 확인합니다.
  7. Constraints 분리 — 06장 프로젝트에서 사용할 XDC를 독립 파일로 관리하고 기존 Clock / Reset 설정을 유지합니다. GPIO용 SW/LED 핀과 Wrapper 포트명은 SECTION 06~07에서 확정합니다. 01장 XDC 파일을 직접 편집하지 않습니다.

화면 확인 06장 .xpr, Design Sources의 soc06_axi_gpio.bd, Top soc06_axi_gpio_wrapper, 기존 IP 9개 정상 상태를 확인한 후에만 SECTION 03으로 넘어갑니다. 실제 XDC·BD 소스 경로가 01장 폴더를 직접 가리키면 복사 상태를 먼저 점검합니다.

SECTION 03

AXI GPIO 추가

  1. Vivado의 IP Integrator → Block Design을 엽니다.
  2. Add IP에서 AXI GPIO를 검색합니다.
  3. AXI GPIO를 추가하여 axi_gpio_0가 나타나는지 확인합니다.

화면 확인 axi_gpio_0에 S_AXI, GPIO, GPIO2 인터페이스가 표시됩니다.

하드웨어의 IP 이름 axi_gpio_0는 이후 Vitis의 GPIO 주소 정보와 연결됩니다.

  3. 아래 표처럼 두 채널의 방향과 폭을 지정하고 OK를 클릭합니다.

SECTION 05

AXI · Clock · Reset 연결

  1. axi_gpio_0/S_AXI에서 Run Connection Automation을 실행합니다.
  2. CPU의 M_AXI_DP와 GPIO의 S_AXI 사이에 axi_smc(AXI SmartConnect)가 생성되는지 확인합니다.
  3. s_axi_aclk는 시스템 100 MHz 클록, s_axi_aresetn은 활성 Low 리셋 경로에 연결되는지 확인합니다.
microblaze_riscv_0 / M_AXI_DP → axi_smc → axi_gpio_0 / S_AXI

화면 확인 Vivado Validate Design에서 AXI, Clock, Reset 연결 오류가 없어야 합니다.

SECTION 08

Address Editor와 GPIO 레지스터

  1. Block Design의 Address Editor를 엽니다.
  2. axi_gpio_0/S_AXI의 기준 주소가 0x40000000인지 확인합니다.
  3. 아래 네 레지스터는 기준 주소에 오프셋을 더해 접근한다는 점을 확인합니다.
레지스터오프셋이 장에서 하는 일
GPIO_DATA+0x00LED 출력값
GPIO_TRI+0x04LED 방향
GPIO2_DATA+0x08스위치 입력값
GPIO2_TRI+0x0C스위치 방향

실제 주소 범위: 0x40000000 ~ 0x4000FFFF(64 KiB 할당 영역). Local BRAM은 0x00000000 ~ 0x00003FFF(16 KiB)입니다. 64 KiB는 주변장치에 할당한 주소 범위이지 GPIO 데이터의 크기가 아닙니다.

SECTION 13

main.c 작성 — 자동 제공 파일과 직접 작성 코드

Vitis의 Sources → src → main.c에 아래 코드를 입력합니다. 아래는 동작을 이해하기 위한 간결 코드입니다. 저장소의 실습 소스 main.c는 Classic/SDT 초기화 분기와 Watch용 상태 변수를 포함한 별도 구현입니다. 두 소스를 섞어 붙여넣지 않고 하나를 선택하여 사용합니다.

#include "xparameters.h"  // Vitis 자동 생성: GPIO 주소 정보
#include "xgpio.h"        // Vitis 자동 제공: AXI GPIO 제어 함수
#include "xstatus.h"      // Vitis 자동 제공: 성공·실패 값

#define LED_CH  1         // 직접 지정: Channel 1, LED 출력
#define SW_CH   2         // 직접 지정: Channel 2, Switch 입력

XGpio Gpio;               // 직접 선언: GPIO를 제어할 변수

int main(void)
{
    // 1. AXI GPIO 초기화
    if (XGpio_Initialize(&Gpio, XPAR_XGPIO_0_BASEADDR)
        != XST_SUCCESS)
        return XST_FAILURE;

    // 2. 입출력 방향 지정 (0: 출력, 1: 입력)
    XGpio_SetDataDirection(&Gpio, LED_CH, 0x0000);
    XGpio_SetDataDirection(&Gpio, SW_CH,  0xFFFF);

    // 3. Switch 값을 읽어서 LED에 계속 출력
    while (1) {
        u32 sw = XGpio_DiscreteRead(&Gpio, SW_CH);
        XGpio_DiscreteWrite(&Gpio, LED_CH, sw);
    }

    return 0;
}
코드에 나온 이름누가 준비하나요?무엇인가요?
xparameters.hVitis 자동 생성하드웨어 주소 정의
xgpio.hVitis 자동 제공GPIO 드라이버 함수
xstatus.hVitis 자동 제공성공·실패 상태값
XPAR_XGPIO_0_BASEADDRVitis 자동 생성현재 GPIO의 기준 주소
LED_CH, SW_CH직접 지정LED 채널 1, Switch 채널 2
Gpio, sw직접 선언제어 대상과 읽은 스위치 값

함수 맨 끝의 return 0;은 정상 종료값을 반환한다는 뜻입니다. 다만 현재는 while (1)을 계속 실행하므로 보통 이 줄에 도달하지 않습니다.

입력할 파일은 main.c 하나입니다. BSP 헤더를 복사하거나 직접 만들지 않습니다. xil_types.h의 u32는 드라이버가 포함한 자료형 정의를 통해 사용합니다.

SECTION 14

C 코드 한 줄씩 이해

처음 사용하는 GPIO 드라이버 프로그램입니다. 자동 제공되는 함수·상수와 직접 정한 변수명을 구분하면서 위에서 아래로 한 줄씩 읽습니다.

① GPIO 주소와 함수 가져오기

#include "xparameters.h"
#include "xgpio.h"
#include "xstatus.h"
코드쉽게 읽기
#include필요한 정의가 들어 있는 헤더를 사용하겠다는 뜻
xparameters.hVivado에서 만든 GPIO의 주소를 알려 줌
xgpio.hGPIO를 초기화·읽기·쓰기 할 함수들을 제공
xstatus.h성공인지 실패인지 확인할 값 제공

② 내가 사용할 채널과 변수 지정

#define LED_CH  1
#define SW_CH   2
XGpio Gpio;
코드쉽게 읽기
#define LED_CH 1LED는 GPIO 채널 1에 연결
#define SW_CH 2스위치는 GPIO 채널 2에 연결
XGpioAMD가 제공하는 GPIO 관리 자료형
Gpio내가 만든 GPIO 관리 변수의 이름

③ GPIO 초기화

if (XGpio_Initialize(&Gpio, XPAR_XGPIO_0_BASEADDR)
    != XST_SUCCESS)
    return XST_FAILURE;
이름쉽게 읽기
XGpio_Initialize()GPIO 장치를 사용할 준비를 함
&Gpio초기화할 GPIO 변수의 위치(주소)를 전달
XPAR_XGPIO_0_BASEADDRVitis가 알려준 실제 GPIO 기준 주소를 전달
!= XST_SUCCESS초기화에 실패했는지 검사
return XST_FAILURE;실패하면 프로그램을 종료

if는 괄호 안 조건을 검사합니다. !=는 두 값이 서로 다르다는 뜻입니다. 초기화 결과가 XST_SUCCESS와 다르면 return을 실행하여 여기서 끝냅니다.

Vitis 화면의 회색 InstancePtr:, EffectiveAddr:는 Inlay Hints(인레이 힌트, 인자 이름 보조 설명)입니다. 설명만 표시되며 직접 타이핑하지 않습니다.

④ LED는 출력, 스위치는 입력

XGpio_SetDataDirection(&Gpio, LED_CH, 0x0000);
XGpio_SetDataDirection(&Gpio, SW_CH,  0xFFFF);
인자의미
&Gpio설정할 GPIO 장치
LED_CH, SW_CH설정할 채널 1 또는 2
0x000016비트 모두 0 → LED 출력
0xFFFF16비트 모두 1 → 스위치 입력
출력(LED)0000 0000 0000 0000입력(SW)1111 1111 1111 1111

Vitis에 표시되는 Channel:, DirectionMask:도 각각 채널 번호와 입력·출력 설정값을 가리킵니다.

⑤ 스위치를 읽어서 LED에 출력

while (1) {
    u32 sw = XGpio_DiscreteRead(&Gpio, SW_CH);
    XGpio_DiscreteWrite(&Gpio, LED_CH, sw);
}
코드쉽게 읽기
while (1)멈추지 않고 계속 반복
u3232비트 부호 없는 정수형
sw읽은 스위치 상태를 보관할 변수
XGpio_DiscreteRead(&Gpio, SW_CH)채널 2의 입력값을 읽음
XGpio_DiscreteWrite(&Gpio, LED_CH, sw)읽은 값을 채널 1의 LED에 출력
SW0 · SW2 ON → sw = 0x0005 → LED0 · LED2 ON

return 0;은 main()이 종료될 때 반환하는 값입니다. 현재 프로그램은 무한 반복하므로 정상 실행 중에는 도달하지 않습니다.

SECTION 15

Build → clangd 헤더 갱신 → Debug · Inlay Hints

새 Platform을 만든 직후 또는 main.c에 헤더 파일의 빨간 밑줄이 보이면 Platform → Application 순서로 Build하고, 코드 분석기만 갱신합니다. Ubuntu나 Vitis를 재부팅하지 않습니다.

  1. Platform Build 확인 — Vitis Explorer에서 soc06_axi_gpio_platform [Platform]을 선택합니다. 왼쪽 아래 FLOW → Build를 실행하고 오류 없이 끝났는지 확인합니다. 앞 절에서 이미 정상 빌드했다면 중복 실행할 필요는 없습니다.
  2. Application Build — 왼쪽 아래 FLOW → Component에서 soc06_axi_gpio [Application]을 선택하고 Build를 클릭합니다. Build Finished successfully와 ELF 생성을 확인합니다.
  3. 헤더 인식 갱신 — main.c에 빨간 밑줄이 남아 있으면 Ctrl + Shift + P → clangd: Restart language server 검색 → 해당 명령을 실행합니다. clangd(클랭디, C/C++ 코드 분석 서버)만 다시 시작하며 Vitis 프로젝트와 실행 중인 컴퓨터는 그대로 유지합니다.
  4. 빨간 밑줄 재확인 — 잠시 후 xparameters.h, xgpio.h, xstatus.h에 표시됐던 코드 분석 오류가 사라졌는지 확인합니다. Application Build 자체가 실패했다면 빨간 밑줄만 지우려 하지 말고 Build 출력의 실제 컴파일 오류부터 해결합니다.
  5. Settings → launch.json을 열고 soc06_axi_gpio.bit, soc06_axi_gpio.elf, microblaze_riscv_0를 확인합니다.
  6. Debug로 진입합니다. Hart #0 — PAUSED ON BREAKPOINT가 표시되면 main()에서 멈춘 상태입니다.
  7. Continue (▶)를 눌러 프로그램을 계속 실행합니다.

Inlay Hints 표시 설정

Vitis 상단의 File → Preferences → Open Settings (UI)에서 Inlay Hints를 검색하고 Editor › Inlay Hints: Enabled → On으로 설정합니다. 직접 입력하는 소스 코드에는 포함되지 않습니다.

Build는 성공했는데 코드에 빨간 밑줄이 남을 때
  1. 먼저 soc06_axi_gpio_platform [Platform]의 Build 성공 여부를 확인합니다.
  2. soc06_axi_gpio [Application]의 Build 성공 여부를 확인합니다.
  3. Ctrl + Shift + P → clangd: Restart language server를 실행하고 main.c를 다시 확인합니다.

판정 기준: 실제 컴파일·링크가 성공했는데 편집기에만 빨간 밑줄이 남으면 코드 분석기 경로 갱신 문제일 수 있습니다. 반대로 컴파일러가 fatal error: xparameters.h: No such file or directory처럼 출력한다면 Platform/Domain/BSP 연결을 먼저 확인해야 합니다. #include에 컴퓨터의 절대 경로를 직접 넣거나 헤더를 수동 복사하지 않습니다.

기존 확인 사례: 06장에서는 Vitis 재실행 후 오류 표시가 사라진 사례가 있었습니다. 이제는 재실행 전에 clangd만 다시 시작하는 방법을 우선 적용합니다. 해당 방법의 성공 여부는 실행 화면에서 확인합니다.

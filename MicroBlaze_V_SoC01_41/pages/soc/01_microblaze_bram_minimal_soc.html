Basys3 SoC + NPU · SoC 01

MicroBlaze V + BRAM 최소 SoC

Basys3의 Artix-7 FPGA 내부에 MicroBlaze V(마이크로블레이즈 브이) CPU와 Local BRAM을 구성하고, Clock·Reset·Debug까지 연결해 이후 AXI 주변장치와 NPU를 확장할 기준 SoC를 만든다.

Basys3MicroBlaze VBRAMLMBIP IntegratorVivado 2026.1 기준

CPU

FPGA Fabric에 구현되는 MicroBlaze V를 사용한다.

Memory

ILMB/DLMB를 통해 공통 Block RAM에 접근한다.

완료 기준

MicroBlaze V · Local BRAM 계층 생성과 Block Design 저장까지 확인한다. 외부 Clock/Reset 연결 및 첫 Validate는 SoC 02에서 진행한다.

SECTION 01

최소 SoC 구성 범위

SoC 01은 이후 확장의 기준이 되는 MicroBlaze V · Local BRAM IP 기본 구성을 생성하고 저장한다. Clock/Reset의 외부 연결과 빌드는 SoC 02에서 완료하며, GPIO·UART·Timer·Interrupt·Custom AXI IP·NPU는 포함하지 않는다.

① CPU

MicroBlaze V를 FPGA 내부에 구성한다.

② Local Memory

명령과 데이터를 저장할 BRAM을 붙인다.

③ Clock / Reset

자동 생성된 Clock/Reset IP와 내부 연결을 확인한다. Basys3 외부 입력 포트 연결은 SoC 02에서 완료한다.

④ 저장 기준

Local Memory 16 KB 구성과 Block Design 저장을 확인한다. Validate 및 후속 빌드는 SoC 02 연결 이후 진행한다.

MicroBlaze V를 사용한다. CPU는 32비트 RV32IM, 캐시 없음, Machine mode로 구성한다.
Basys3 100 MHz → Clocking Wizard → MicroBlaze V → ILMB/DLMB → Local BRAM
SECTION 02

Basys3 하드웨어 기준

Basys3는 Artix-7 XC7A35T-1CPG236C를 사용하며, 보드에는 100 MHz 단일 Oscillator가 있다. Digilent Reference Manual은 이 Clock이 FPGA의 W5 핀에 연결되어 있음을 명시한다.

기준 Clock100 MHzClocking Wizard 입력
Clock PinW5Top/BD 외부 Clock 포트와 XDC 연결
Reset 입력Center Button BTNC, pin U18실습용 외부 Reset으로 사용

Local Memory는 외부 DDR이 아니라 FPGA 내부 Block RAM을 사용한다. Basys3의 SPI Flash는 FPGA Configuration 저장장치이며 MicroBlaze V Local BRAM과 역할이 다르다.
SECTION 03

MicroBlaze V 내부 구조

MicroBlaze V는 AMD FPGA에 구현하도록 설계된 RISC Soft Processor이다. 내부에는 Program Counter, Instruction Decode, Register File, ALU 등이 있고 양쪽에 Instruction-side/Data-side bus interface가 있다.

PC → Instruction-side Bus → ILMB → BRAM → Instruction Fetch Load/Store → Data-side Bus → DLMB → BRAM → Data Read/Write

핵심은 “CPU가 BRAM 하나를 쓴다”에서 끝내지 않고, 명령어 Fetch 경로와 Data Load/Store 경로가 논리적으로 분리되어 있다는 것을 Block Design에서 확인하는 것이다.

SECTION 04

ILMB · DLMB · BRAM 관계

LMB(Local Memory Bus)는 FPGA 내부 Block RAM에 빠르게 접근하기 위한 간결한 Local Bus이다. AMD UG1711는 Instruction LMB와 Data LMB가 각각 LMB BRAM Interface Controller를 통해 공통 Block RAM에 연결되는 구성을 일반적인 MicroBlaze V Local Memory 구조로 설명한다.

경로버스와 컨트롤러도착점
microblaze_riscv_0 / ILMBilmb_v10 → lmb_bram_if_cntlr공통 Block Memory Generator
microblaze_riscv_0 / DLMBdlmb_v10 → lmb_bram_if_cntlr공통 Block Memory Generator
인터페이스주 역할실행 관점
ILMBInstruction Local Memory BusPC가 가리키는 명령어 Fetch
DLMBData Local Memory Bus변수·Stack·Data Load/Store
BRAMProgram + Data Local Memory초기 Bare-metal 실행 저장공간
MicroBlaze V의 Vector Base Address는 일반적으로 Local Memory의 0x00000000을 기준으로 사용한다. 실제 프로그램 배치와 linker 영역은 SoC 03의 Software 실행 단계에서 확인한다.
SECTION 05

Vivado 프로젝트 생성

  1. Create Project

    Vivado에서 Create Project를 선택하고 새 RTL Project를 만든다.

  2. Project Type

    RTL Project를 선택한다. 지금 단계에서는 Verilog 기능 모듈을 추가하지 않아도 된다.

  3. Target Device

    재현성을 위해 Part 기준으로 xc7a35tcpg236-1을 선택한다. Digilent Board File이 설치되어 있다면 Board 탭의 Basys3를 선택해도 된다.

  4. 프로젝트 이름

    예: soc01_microblaze_bram. 경로에는 한글·공백·특수문자를 가급적 사용하지 않는다.

Sources가 비어 있어도 정상이다. 핵심 회로는 IP Integrator Block Design에서 구성한다.
SECTION 06

IP Integrator에서 Block Design 생성

  1. Flow Navigator → IP Integrator

    Create Block Design을 선택한다.

  2. Design Name

    soc01_mb_bram으로 지정한다. 이후 HDL Wrapper 이름과 연결되므로 의미 있는 이름을 사용한다.

  3. 빈 Diagram 확인

    Diagram Canvas가 열리면 아직 아무 IP도 없는 상태가 정상이다.

Vivado Project → IP Integrator → soc01_mb_bram.bd
SECTION 07

MicroBlaze V IP 추가

  1. Add IP

    Diagram의 + 또는 우클릭 → Add IP를 선택한다.

  2. MicroBlaze V 검색

    MicroBlaze V를 검색하여 추가한다. CPU 인스턴스는 microblaze_riscv_0로 확인한다.

  3. 단독 CPU 상태 확인

    Canvas에 microblaze_riscv_0가 추가되고 ILMB, DLMB, Clock, Reset, Debug/AXI 관련 인터페이스가 보이는지 확인한다.

인스턴스 뒤의 _0, _1 번호는 프로젝트 상황에 따라 달라질 수 있다. 번호가 아니라 IP 종류와 인터페이스를 기준으로 확인한다.

CPU 설정은 32비트 주소·RV32IM, Area 최적화, 캐시·FPU·Atomic·Compressed·RV32E·MMU 없음으로 맞춘다. Debug는 활성화하고 MDM V를 연결한다.

MicroBlaze V를 추가하면 Designer Assistance가 활성화된다. Run Block Automation을 실행한다.

Block Automation 이후 구조

그림을 “블록이 많이 생겼다”로 끝내지 말고 아래 순서로 추적한다.

Local Memory Hierarchy를 펼쳐서 확인

microblaze_riscv_0_local_memory와 같은 Hierarchical Block을 열어 ILMB Controller, DLMB Controller, Block Memory Generator가 실제로 존재하는지 확인한다.

여기까지 확인했으면 “MicroBlaze V와 BRAM이 연결되어 있다”를 그림이 아니라 실제 IP 계층으로 검증한 것이다.
SECTION 10

Clock · Reset 연결 준비

Block Automation으로 생성된 Clocking Wizard와 Processor System Reset의 존재 및 내부 연결을 확인한다. 현재는 외부 Basys3 Clock/Reset이 미연결일 수 있으며, Run Connection Automation과 외부 포트의 실제 연결은 SoC 02 SECTION 12에서 진행한다.

Clock — SoC 02에서 연결할 경로

Basys3 W5 · 100 MHz → Clocking Wizard clk_in1 → clk_out1 → MicroBlaze V / LMB / Reset System

Reset — SoC 02에서 연결할 경로

Basys3 BTNC · U18 → ext_reset_in → Processor System Reset → mb_reset / bus_struct_reset / peripheral_aresetn

SoC 02에서 완료할 필수 연결

  • Clocking Wizard locked → Processor System Reset dcm_locked
  • Clocking Wizard clk_out1 → MicroBlaze V Clock 및 Local Memory Clock
  • 외부 Reset → ext_reset_in
  • MicroBlaze V Reset ← mb_reset
후속 연결 시 주의: Board Flow를 사용하지 않는 경우에도 clk_wiz/locked와 proc_sys_reset/dcm_locked 연결을 빠뜨리면 안 된다. Reset이 정상 해제되지 않아 CPU가 계속 Reset 상태에 머물 수 있다.
Reset 극성: Processor System Reset의 외부 Reset 입력은 Active-High/Active-Low 설정이 가능하다. 이 실습에서는 Basys3 BTNC를 누르면 High가 되는 조건에 맞춰 Active-High 입력으로 맞춘다. SoC 02에서 Reset 동기화와 출력 극성을 더 깊게 다룬다.

MDM V/Debug_SYS_Rst → Processor System Reset/mb_debug_sys_rst 및 미사용 aux_reset_in의 연결/고정도 SoC 02에서 설정하고 검증한다.

SECTION 11

Basys3 XDC — 필요한 줄만 원본에서 활성화

Digilent Basys-3-Master.xdc를 프로젝트에 추가하고 Clock과 Center Button Reset에 사용할 제약을 확인한다. 외부 포트 clk, btnC의 실제 연결과 이름 일치는 SoC 02에서 완료한다.

## Clock signal
set_property -dict { PACKAGE_PIN W5 IOSTANDARD LVCMOS33 } [get_ports clk]
create_clock -add -name sys_clk_pin -period 10.00 -waveform {0 5} [get_ports clk]

## Center Button : Reset
set_property -dict { PACKAGE_PIN U18 IOSTANDARD LVCMOS33 } [get_ports btnC]
XDC의미검증
PACKAGE_PIN W5Basys3 100 MHz oscillatorReference Manual의 Oscillators/Clocks 절과 일치
period 10.00100 MHz의 1주기 = 10 nsTiming Engine에 Primary Clock 정의
PACKAGE_PIN U18Center Push ButtonDigilent Master XDC의 btnC
아래 XDC는 연결 완료 시 적용할 기준이다. SoC 01에서 외부 포트가 아직 없다면 Validate Design을 실행하지 않는다. Block Design에서 생성된 외부 포트 이름이 clk_0, reset_0처럼 되어 있다면 XDC를 억지로 바꾸기 전에 포트 이름을 먼저 의도한 이름으로 정리한다. HDL/BD 포트명 ↔ XDC get_ports 이름이 정확히 같아야 한다.
SECTION 12

Diagram 저장 · IP 구성 확인

  1. Diagram 저장

    Ctrl+S로 soc01_mb_bram.bd를 저장한다.

  2. MicroBlaze V · Local Memory 확인

    microblaze_riscv_0 및 Local Memory 계층에 ILMB/DLMB Controller와 16 KB BRAM이 존재하는지 확인한다.

  3. Clock/Reset IP 확인

    자동 생성된 Clocking Wizard 및 Processor System Reset이 존재하는지 확인한다.

SUMMARY

SoC 01 완료 확인

  • Target이 Basys3의 XC7A35T-1CPG236C이다.
  • soc01_mb_bram.bd가 생성되었다.
  • MicroBlaze V와 MDM V가 존재한다.
  • Local Memory 16 KB, ECC None, Cache None이다.
  • ILMB와 DLMB가 Local BRAM으로 연결된다.
  • MDM V Debug Module이 연결된다.
  • Clocking Wizard와 Processor System Reset IP가 생성되어 있다.
  • Basys-3-Master.xdc가 프로젝트에 등록되어 있고 W5 / U18 / 10 ns 제약을 확인했다.
  • soc01_mb_bram.bd를 저장했다.
  • 아직 GPIO/UART/Timer/Interrupt/NPU를 추가하지 않았다.

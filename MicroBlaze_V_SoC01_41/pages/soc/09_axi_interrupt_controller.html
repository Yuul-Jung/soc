현재 문서는 09장 실습 기본틀입니다. 성공 이미지, INTC 주소, BSP 매크로 및 실행 수치는 실제 검증한 뒤 반영합니다.

THEORY 01

Polling에서 Interrupt로

08장에서는 CPU가 Timer 만료 상태를 반복 확인했습니다. 09장에서는 Timer가 인터럽트를 발생시키면 CPU가 등록된 Handler를 실행합니다.

확인 · 08장 Polling 코드와 09장 Interrupt 코드의 차이를 비교합니다.
THEORY 02

AXI Timer → INTC → CPU

Timer의 interrupt 출력은 INTC의 intr 입력에 연결되고, INTC의 irq 출력은 MicroBlaze V의 INTERRUPT 입력에 연결됩니다.

확인 · AXI 주소 버스와 인터럽트 신호선을 구별합니다.
axi_timer_0/interrupt
        │
        ▼
axi_intc_0/intr[0]
axi_intc_0/irq
        │
        ▼
microblaze_riscv_0/INTERRUPT
        │
        ▼
XTmrCtr_InterruptHandler → Callback → Main → LED0
THEORY 03

AXI Interrupt Controller의 역할

인터럽트 원인별 허용·대기·처리 승인을 관리합니다. 이번에는 Timer 입력 하나만 사용합니다.

확인 · PG099에서 IER, IPR, IAR, MER의 의미를 확인합니다.
레지스터기능
IER인터럽트 입력별 허용
IPR대기 중인 인터럽트 확인
IAR인터럽트 처리 승인
MER마스터 인터럽트 허용
THEORY 04

Timer 인터럽트 신호

Timer 0의 인터럽트 발생 상태는 T0INT로 확인하고, 해당 상태는 1을 기록하여 해제합니다.

확인 · PG079의 Timer 0 인터럽트 비트와 자동 재적재 동작을 확인합니다.
THEORY 05

ISR와 Main Loop의 역할

Timer Driver의 Handler가 원인을 처리하고 사용자 Callback을 호출합니다. Callback에서는 발생 횟수와 이벤트를 기록하며, LED 출력은 Main에서 처리합니다.

확인 · 인터럽트 등록과 활성화는 Vitis 2024.2 실제 BSP에 맞춥니다.

09.1장 · Interrupt C 코드 쉬운 풀이 독립 페이지 열기

CODE GUIDE · 07.1 STYLE

09장 Interrupt C 코드 쉽게 이해하기

07.1장과 같은 순서로 코드 → 쉬운 풀이 → CPU·하드웨어에서 일어나는 일을 연결합니다. 같은 코드를 여러 번 길게 반복하지 않고 핵심 구문만 분리했습니다.

검증 구분 · 아래는 09장용 교육 예제 초안입니다. xparameters.h의 장치 ID·주소·SDT 여부 및 실제 빌드·실행 결과는 아직 확인되지 않았습니다. 인터럽트 동작 성공 사례로 사용하지 않습니다.
Timer 만료 → INTC → CPU → TimerCallback → timer_event → Main → GPIO LED0

01 · 헤더 파일 — 준비된 기능 가져오기

#include "xparameters.h"
#include "xtmrctr.h"
#include "xgpio.h"

코드 풀이 — 이 코드가 무엇을 하는가? 하드웨어 장치 이름과 Timer·GPIO 제어 함수를 사용하도록 선언합니다. 헤더를 포함했다고 실제 하드웨어가 새로 생기지는 않습니다.

CPU·하드웨어에서는? Vivado에서 만든 장치 구성 정보는 XSA와 BSP를 통해 C 프로그램에 전달됩니다.

02 · Timer 간격 — 08장 값 유지

#define TIMER0 0U
#define TIMER_RESET_VALUE 49999998U

코드 풀이 — 이 코드가 무엇을 하는가? Timer 0을 사용하며, 이미 검증된 08장의 재적재 값을 유지합니다. 100 MHz 설정을 전제로 약 0.5초 주기를 목표로 합니다.

CPU·하드웨어에서는? Timer는 CPU가 계속 읽지 않아도 자체 클록을 세며 동작합니다.

03 · 변수 세 개 — 발생 횟수와 LED 기억

volatile u32 interrupt_count = 0U;
volatile u32 timer_event = 0U;
volatile u32 led_state = 0U;

코드 풀이 — 이 코드가 무엇을 하는가? 첫 변수는 인터럽트 횟수, 두 번째는 새 이벤트 발생 표시, 세 번째는 LED0의 현재 상태입니다. volatile은 실행 도중 값이 예상 밖의 시점에 바뀔 수 있음을 컴파일러에 알립니다.

CPU·하드웨어에서는? Callback과 Main이 같은 메모리 변수를 사용합니다. volatile만으로 동시 접근 문제가 모두 해결되는 것은 아닙니다.

04 · TimerCallback() — 인터럽트가 오면 기록

static void TimerCallback(void *CallBackRef, u8 TmrCtrNumber)
{
    (void)CallBackRef;
    (void)TmrCtrNumber;
    interrupt_count++;
    timer_event = 1U;
}

코드 풀이 — 이 코드가 무엇을 하는가? Timer 인터럽트가 처리될 때 드라이버가 이 함수를 호출합니다. 발생 횟수를 하나 증가시키고 Main에 알릴 표시만 남깁니다.

CPU·하드웨어에서는? CPU는 현재 실행 흐름을 잠시 중단하고 인터럽트 처리 경로에 진입합니다. Callback 자체에서 LED 레지스터를 쓰지는 않습니다.

05 · InitTimer() — 반복 인터럽트 준비

XTmrCtr_SetHandler(&Timer, TimerCallback, &Timer);
XTmrCtr_SetOptions(&Timer, TIMER0,
    XTC_DOWN_COUNT_OPTION | XTC_AUTO_RELOAD_OPTION | XTC_INT_MODE_OPTION);
XTmrCtr_SetResetValue(&Timer, TIMER0, TIMER_RESET_VALUE);

코드 풀이 — 이 코드가 무엇을 하는가? Callback 연결 → 감소 계수·자동 재적재·인터럽트 사용 → 시작값 설정 순서입니다. 08장 Polling과 가장 크게 달라진 부분은 XTC_INT_MODE_OPTION입니다.

CPU·하드웨어에서는? Timer의 만료 신호가 발생하면 AXI INTC를 거쳐 CPU로 전달될 수 있도록 준비합니다.

06 · SetupInterruptSystem() — 인터럽트 길 연결

XIntc_Connect(&Intc, TIMER_INTR_ID,
    (XInterruptHandler)XTmrCtr_InterruptHandler, &Timer);
XIntc_Enable(&Intc, TIMER_INTR_ID);
Xil_ExceptionRegisterHandler(XIL_EXCEPTION_ID_INT,
    (Xil_ExceptionHandler)XIntc_InterruptHandler, &Intc);

코드 풀이 — 이 코드가 무엇을 하는가? Classic 방식 예시입니다. Timer 인터럽트 번호와 처리 함수를 연결하고, 해당 입력 및 CPU 예외 처리 경로를 허용합니다. SDT 방식에서는 XSetupInterruptSystem()을 사용합니다.

CPU·하드웨어에서는? Timer → AXI INTC → CPU → Timer Driver → TimerCallback 순서의 연결 관계가 만들어집니다.

07 · main() — LED를 변경하는 곳

XTmrCtr_Start(&Timer, TIMER0);
while (1) {
    if (timer_event != 0U) {
        timer_event = 0U;
        led_state ^= 1U;
        XGpio_DiscreteWrite(&Gpio, LED_CHANNEL, led_state);
    }
}

코드 풀이 — 이 코드가 무엇을 하는가? Timer를 시작한 뒤 Main은 이벤트 표시만 확인합니다. 이벤트가 있으면 표시를 지우고 LED0 값을 0↔1로 바꾸어 GPIO에 기록합니다.

CPU·하드웨어에서는? Timer 상태 레지스터를 반복 읽는 08장 Polling과 달리, 여기서는 인터럽트가 남긴 소프트웨어 이벤트를 확인합니다. Main은 여전히 반복 루프를 실행하므로 완전한 저전력 대기 방식은 아닙니다.

전체 main.c — 한 번에 복사하기

위 구문이 포함된 전체 교육용 코드입니다. 실제 Vitis 2024.2 BSP 헤더 확인 후 최종 적용합니다.

#include "xparameters.h"     // 하드웨어 주소 및 장치 번호
#include "xtmrctr.h"         // AXI Timer 드라이버
#include "xgpio.h"           // AXI GPIO 드라이버
#include "xstatus.h"         // 성공/실패 반환값
#include "xil_exception.h"   // CPU 인터럽트 처리

#ifdef SDT
#include "xinterrupt_wrap.h" // SDT 기반 인터럽트 연결
#else
#include "xintc.h"          // Classic 기반 AXI INTC 드라이버
#endif

#define TIMER0             0U
#define LED_CHANNEL        1U
#define TIMER_RESET_VALUE  49999998U // 08장에서 사용한 값

#ifndef SDT
// 다음 이름은 실제 xparameters.h 확인 후 확정
#define TIMER_DEVICE_ID    XPAR_TMRCTR_0_DEVICE_ID
#define GPIO_DEVICE_ID     XPAR_GPIO_0_DEVICE_ID
#define INTC_DEVICE_ID     XPAR_INTC_0_DEVICE_ID
#define TIMER_INTR_ID      XPAR_INTC_0_TMRCTR_0_VEC_ID
#else
// 다음 주소 매크로 역시 실제 BSP를 확인
#define TIMER_BASEADDR     XPAR_XTMRCTR_0_BASEADDR
#define GPIO_BASEADDR      XPAR_XGPIO_0_BASEADDR
#endif

static XTmrCtr Timer;
static XGpio Gpio;
#ifndef SDT
static XIntc Intc;
#endif

volatile u32 interrupt_count = 0U; // 발생한 인터럽트 횟수
volatile u32 timer_event = 0U;     // Main에 전달할 이벤트
volatile u32 led_state = 0U;       // LED0 상태

// Timer 드라이버에서 호출하는 사용자 Callback
static void TimerCallback(void *CallBackRef, u8 TmrCtrNumber)
{
    (void)CallBackRef;
    (void)TmrCtrNumber;
    interrupt_count++;
    timer_event = 1U;
}

static int InitGpio(void)
{
#ifndef SDT
    return XGpio_Initialize(&Gpio, GPIO_DEVICE_ID);
#else
    return XGpio_Initialize(&Gpio, GPIO_BASEADDR);
#endif
}

static int InitTimer(void)
{
    int status;
#ifndef SDT
    status = XTmrCtr_Initialize(&Timer, TIMER_DEVICE_ID);
#else
    status = XTmrCtr_Initialize(&Timer, TIMER_BASEADDR);
#endif
    if (status != XST_SUCCESS) return XST_FAILURE;

    status = XTmrCtr_SelfTest(&Timer, TIMER0);
    if (status != XST_SUCCESS) return XST_FAILURE;

    XTmrCtr_SetHandler(&Timer, TimerCallback, &Timer);
    XTmrCtr_SetOptions(&Timer, TIMER0,
        XTC_DOWN_COUNT_OPTION | XTC_AUTO_RELOAD_OPTION | XTC_INT_MODE_OPTION);
    XTmrCtr_SetResetValue(&Timer, TIMER0, TIMER_RESET_VALUE);
    return XST_SUCCESS;
}

static int SetupInterruptSystem(void)
{
    int status;
#ifndef SDT
    status = XIntc_Initialize(&Intc, INTC_DEVICE_ID);
    if (status != XST_SUCCESS) return XST_FAILURE;
    status = XIntc_Connect(&Intc, TIMER_INTR_ID,
        (XInterruptHandler)XTmrCtr_InterruptHandler, &Timer);
    if (status != XST_SUCCESS) return XST_FAILURE;
    status = XIntc_Start(&Intc, XIN_REAL_MODE);
    if (status != XST_SUCCESS) return XST_FAILURE;
    XIntc_Enable(&Intc, TIMER_INTR_ID);
    Xil_ExceptionInit();
    Xil_ExceptionRegisterHandler(XIL_EXCEPTION_ID_INT,
        (Xil_ExceptionHandler)XIntc_InterruptHandler, &Intc);
    Xil_ExceptionEnable();
#else
    status = XSetupInterruptSystem(&Timer,
        (XInterruptHandler)XTmrCtr_InterruptHandler,
        Timer.Config.IntrId, Timer.Config.IntrParent,
        XINTERRUPT_DEFAULT_PRIORITY);
    if (status != XST_SUCCESS) return XST_FAILURE;
#endif
    return XST_SUCCESS;
}

int main(void)
{
    if (InitGpio() != XST_SUCCESS) return XST_FAILURE;
    if (InitTimer() != XST_SUCCESS) return XST_FAILURE;
    if (SetupInterruptSystem() != XST_SUCCESS) return XST_FAILURE;

    XGpio_DiscreteWrite(&Gpio, LED_CHANNEL, led_state);
    XTmrCtr_Start(&Timer, TIMER0);

    while (1) {
        if (timer_event != 0U) {
            timer_event = 0U;
            led_state ^= 1U;
            XGpio_DiscreteWrite(&Gpio, LED_CHANNEL, led_state);
        }
    }
}
관찰 변수 · interrupt_count는 증가, timer_event는 0과 1 사이에서 변화, led_state는 0↔1을 기대합니다. 아직 측정된 값은 아닙니다.
